## 3. 数据边界

```text
GameDataVersion（所有账号共享）
  HeroDefinition / EquipmentDefinition / ArtifactDefinition / SetDefinition
                      │ stable definition ID
                      ▼
AccountSnapshot（单一账号拥有状态）
  OwnedHero / OwnedGear / OwnedArtifact
                      │
                      ▼
OptimizationRequest -> BuildResult
```

公共定义不能回答账号拥有什么；账号 OCR 观测不能静默覆盖公共历史。角色裸属性、神器静态属性、装备实例随机词条分别保留来源。条件套装/神器效果没有场景模型时不计入常驻面板。

## 4. 验证证据

- `scripts/verify.ps1` 会重新编译公共数据、字典、覆盖审计和所有合成 fixture；
- Schema 校验覆盖账号、公共数据、采集计划、OCR、Review、layout、pipeline、请求、结果和基准；
- 求解器用完整枚举 oracle 验证分支定界 Top N；
- 100/300/1,000 件合成背包有可复算性能基准；
- 隐藏浏览器验证账号库存、配装、两级 Review、神器强化/精炼和公共装备手工关联；
- Windows OCR 在本项目截图上通过烟雾测试，但没有真实游戏准确率。

## 5. 已知缺口

1. 没有目标国服/国际服渠道和 build 的真实截图；
2. 没有人工清点与采集结果的完整性对照；
3. 没有国服 351 角色、682 装备、147 神器的完整中文稳定 ID 映射；
4. 5 个特殊装备槽位未知，52 个装备显示名存在歧义；
5. 随机副词条池、已强化 roll 次数/概率和大多数套装条件效果未结构化；公开目录的主属性等级曲线不能替代这些账号实例证据；
6. 角色星级/灵感和最终面板结算顺序未用客户端 golden cases 校准；
7. 大背包启发式不是全局最优保证，且求解尚未移入 Web Worker。
