# 领域模型与属性口径

## 已确认的核心对象

角色有七个装备槽：神器、头盔、武器、胸甲/衣服、手套、正位符文、负位符文。公开资料还确认：头盔主属性固定为生命，武器固定为攻击；胸甲、手套和两类符文有不同主属性池；符文副属性可出现攻击速度与技能急速。

## 建议实体

| 实体 | 关键字段 |
|---|---|
| `GameDataVersion` | 地区、渠道、版本线、赛季、build、语言、有效期 |
| `HeroDefinition` | 稳定 ID、别名、元素/流派、基础属性曲线、技能与成长节点 |
| `OwnedHero` | 角色 ID、等级、星级/精进、灵感、额外成长、当前穿戴 |
| `GearDefinition` | 槽位、品质、套装、可用主副词条、强化规则 |
| `OwnedGear` | 账号内稳定 ID、定义 ID、主词条、副词条、强化、锁定、穿戴者 |
| `ArtifactDefinition` | 品质、基础属性曲线、被动效果、穿戴限制 |
| `OwnedArtifact` | 定义 ID、精炼/等级、拥有数量、当前穿戴者 |
| `SetDefinition` | 阈值、静态面板加成、条件战斗效果、互斥/叠加规则 |
| `BuildScenario` | 角色、队伍、敌人、战斗时长、效果 uptime 与假设 |
| `OptimizationRequest` | 目标、约束、固定/排除装备、候选范围、求解设置 |
| `BuildResult` | 七槽位、面板、条件值、目标分数、解释、准确性与数据版本 |

## 已观察到的公共目录结构

2026-11-03 固化的 SSR 页面包含可复算的 Nuxt 状态。当前编译器提取到：351 个英雄、682 条装备定义、147 条神器定义，以及按赛季和普通/`+` 版本分开的 248 个套装家族记录，横跨 `s1` 至 `s9`。这些数字表示“来源页面包含的记录”，不等于当前国服/国际服账号实际可获得数量。

英雄公共记录当前可提供：

- `heroId`、英文名、赛季、品质、元素、定位、近战/远程；
- 一级生命、防御、攻击、重击率、重击伤害、命中、抗性、精通和技能急速；
- 每级成长字段；
- 技能文本、灵感文本、推荐装备/神器/队友的外部 ID。

公共角色定义中的一级基础值与 `perLevelGrowth` 是共享资料；账号角色的实际等级、星级、灵感以及账号观测的无装备基础面板属于账号状态。当前尚未证明公共成长字段可按等级线性外推，且个别重击率字段这样外推会产生明显不合理结果。因此等级大于 1 的角色默认必须提供 `baseStatsOverride`；只有研究请求显式接受未验证成长时才能暂时外推，并保留来源标记。

装备/神器公共记录当前可提供：

- 外部定义 ID、名称、品质、赛季、强化上限和远程素材 URL；
- 主属性组、规范化属性键、初始 roll 范围；
- `+0` 至强化上限的属性曲线；
- 神器各精炼等级效果文本；
- 装备套装效果文本和普通/`+` 变体。

套装文本现采用保守的两层表示：原始 `semanticEffects` 永久保留；只有整句满足“件数前缀 + 已知属性 + 明确数值/单位”的无条件静态描述才生成 `bonuses[].sheetStats`。当前 248 个公共家族中有 144 个通过，条件触发、持续时间、未知术语或单位不匹配会拒绝整句。它们仍是官方 Wiki 文本编译结果，不等于当前客户端公式实测。

`GameData.equipment` 已正式暴露全部 682 条装备定义，而不再只存在于编译中间层。`OwnedGear.definitionId` 可引用公共定义；账号实例仍单独保存随机词条、强化、锁定和穿戴者。682/682 条可由 canonical ID 或 external ID 唯一导入，仅显示名能唯一解析 554 条；其余同名项必须结合稳定 ID、上下文或人工 Review。

其中 5 条特殊装备无法从名称可靠映射到六个普通槽位，编译结果保留为 `unknown`，不能靠猜测强制分类。

## 属性命名

首版至少保留以下独立键：

- `hp_flat`, `hp_pct`
- `atk_flat`, `atk_pct`
- `def_flat`, `def_pct`
- `crit_rate`, `crit_damage`
- `accuracy`, `resistance`
- `enlightenment`
- `skill_haste`, `attack_speed_pct`
- `damage_bonus_pct`, `damage_reduction_pct`

中文 UI 中“效果命中/命中”映射到 `accuracy`，“精通”映射到英文资料的 `Enlightenment`；必须保留原始显示文本，避免翻译变化污染 canonical key。

## 三层数值

1. **Sheet stats**：角色成长、装备主副词条、静态套装、神器静态属性相加后的面板。
2. **Conditional stats**：队长技、灵感、套装/神器触发、队友、敌人和战斗阶段产生的条件属性。
3. **Encounter metrics**：特定技能/循环/敌人条件下的伤害、治疗、护盾或存活指标。

用户提出的“重击率 ≥ 100%、攻击 ≥ 5000、生命 ≥ 60000、命中 ≥ 150”默认属于 sheet constraints；若数值来自战斗触发，UI 必须明确标为条件约束。

角色基础值的优先级是：账号采集得到的 `baseStatsOverride` → 公共目录一级基础值加每级成长 → 无法计算。角色已穿装备时看到的 `observedSheetStats` 只能用于回归核对，不能直接当作裸面板再次叠加装备。星级、灵感和其他成长节点尚未结构化时，结果必须提示未建模，而不能静默忽略。

## 已验证的部分规则

- 角色基础面板例证显示初始重击率 10%、重击伤害 50%，但不能在未覆盖全部角色前断言所有角色相同。
- 公开属性说明称衍生伤害受精通影响且不能重击，精通增伤示例为 `enlightenment / 200`。
- 技能急速：公开说明称每 5 点等于 1% 充能速度；示例 100 急速使 20 秒充能变为 `20 / 1.2 = 16.67s`。
- 公开资料列出的 8/12/16/20 强化档位主属性数值与副词条初始范围，是很好的校验规则，但可能属于特定版本，尚未做国服客户端实测。

## 必须保留的复杂性

- 套装效果不只是加属性，可能依赖命中负面、暴击次数、同流派队友、敌人最大生命等条件。
- 神器可能限定英雄或阵营，并有精炼曲线和触发效果。
- 同名装备可能存在 `+` 版本、品质/赛季变体；显示名不能当稳定 ID。
- 攻击、生命、防御的百分比应作用于哪一层基础值，必须用客户端面板 golden case 反推，未验证前不要硬编码。
